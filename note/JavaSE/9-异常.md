# Java 异常机制

## 一、异常概述

异常是程序在**运行阶段**出现的非正常情况（语法无错误），会打断程序正常执行流程。Java 以**面向对象思想**处理异常，所有异常、错误本质都是对象。

- **编译时异常**：语法写错、关键字拼写错误等，编译器直接拦截，无法运行，不属于异常范畴
- **运行时异常**：代码语法合法，运行过程中因数据、环境、逻辑问题触发的错误，即 Java 异常

## 二、Java 异常体系

Java 所有异常和错误的顶层父类为`java.lang.Throwable`，体系分层如下：

```Plain
Throwable（顶层根类）
├─ Error 系统级错误（无需处理）
└─ Exception 程序可处理异常
   ├─ RuntimeException 运行时异常（非受检异常）
   └─ 普通编译异常（受检异常）
```

> Tips：大部分以able结尾的一般都是接口，able在英语里面就是表达能不能意思，但是Throwable是类不是接口比较特殊。

### 2.1 Error 系统错误

- 定义：JVM 层面的严重、不可恢复错误，由系统资源耗尽、虚拟机异常导致
- 特点：**程序无法捕获、无法处理、无需处理**
- 常见案例：        
  - `StackOverflowError`：栈溢出（递归死循环、方法嵌套过深）
  - `OutOfMemoryError`：内存溢出（创建过多对象、内存泄漏）

### 2.2 Exception 程序异常

开发者可捕获、可处理的异常，分为**编译时异常**和**运行时异常**两类。

> **编译时异常（非运行时异常，你在写代码时候就需要处理的异常）：** 程序正确，但因为外在的环境条件不满足引发。例如：这不是程序本身的逻辑错误，Java编译器强制要求必须处理这类异常，如果不去处理这个异常，程序就会报错。（读取一个硬盘上图片，读取的代码逻辑是正确的，但是这个图片所在的硬盘可能出现坏道，就没法读取这个文件，未雨绸缪提前检测可能会有读取硬盘问题）
>
> **运行期异常（RuntimeException，代码运行时候抛出的异常）：** 这意味着程序存在bug，如数组越界，0被除，空指针....这类异常需要更改程序来避免，Java编译器强制要求处理这类异。如果抛出运行时异常，是要根据抛出的异常的信息去分析程序的错误，**在写代码时候绝大部分情况下不去try-catch运行时异常**。

#### 1. 运行时异常

运行时异常又叫**非受检异常**

- 归属：`RuntimeException` 及其所有子类
- 特点：编译器**不强制**处理，编译不报错，**运行时才抛出异常**
- 成因：大多是代码逻辑问题导致
- 常见异常：        
  - `NullPointerException`：空指针异常（调用 null 对象的方法/属性）
  - `ArrayIndexOutOfBoundsException`：数组下标越界异常
  - `ArithmeticException`：算术异常（除数为0）
  - `ClassCastException`：类型强转异常
  - `IllegalArgumentException`：非法参数异常

#### 2. 编译时异常

编译时异常又叫**受检异常**

- 归属：除 `RuntimeException` 外的所有 `Exception` 子类
- 特点：编译器**强制要求处理**，不处理直接编译报错，**在写代码的时候就应该解决的异常**
- 成因：外部环境、资源问题导致（IO、网络、数据库等）
- 常见异常：        
  - `IOException`：文件IO异常
  - `SQLException`：数据库操作异常
  - `ClassNotFoundException`：类找不到异常
  - `FileNotFoundException`：文件不存在异常

## 三、异常处理

Java 异常处理关键字：`try`、`catch`、`finally`、`throw`、`throws`

### 3.1 try-catch-finally 捕获处理异常

#### 1. 基础语法

```java
try {
    // 可能出现异常的核心业务代码
} catch (异常类型1 e) {
    // 捕获对应异常后的处理逻辑
} finally {
    // 无论是否异常，最终一定会执行的代码
}
```

#### 2. 各代码块作用

- **try 块**：包裹可能抛出异常的代码，一旦出现异常，终止当前 try 内后续代码执行
- **catch 块**：捕获 try 中抛出的指定类型异常，执行容错逻辑，可写多个
- **finally 块**：资源释放专属代码块（关闭文件、流、数据库连接等），**除非JVM退出，否则必执行**

#### 3. 执行流程

1. try 代码无异常：执行 try 全部代码 → 执行 finally → 程序正常结束
2. try 代码有异常：中断 try 执行 → 匹配对应 catch 捕获异常并执行 → 执行 finally

> 需要注意的是，如果catch块中没有抛出异常的话，执行完finally代码会继续向下执行，例如下面这个例子里面的`test`会被打印：
>
> ```java
>  public static void main(String[] args) {
>      try{
>          String str = "hello";
>          System.out.println(str.charAt(5));
>      }catch (StringIndexOutOfBoundsException e){
>          e.printStackTrace();
>      }finally{
>          System.out.println("finally");
>      }
>      System.out.println("test");
>  }
> ```
>
> 结果：
>
> ```bash
> java.lang.StringIndexOutOfBoundsException: Index 5 out of bounds for length 5
> 	...
> finally
> test
> ```

### 3.2 throws 抛出异常

- 作用：定义方法时，**声明该方法可能抛出的异常**，将异常处理权交给方法调用者
- 使用位置：方法签名后
- 适用场景：方法内无法处理异常，需要向上传递

```java
// 声明抛出IO受检异常
public void readFile() throws IOException {
    FileReader fr = new FileReader("test.txt");
}
```

注意：受检异常必须声明或捕获，运行时异常可省略 throws 声明

### 3.3 throw 抛出异常

- 作用：**主动手动抛出一个异常对象**，终止当前方法执行
- 使用位置：方法内部
- 适用场景：参数不合法、业务逻辑不满足，主动触发异常

```java
public void setAge(int age) {
    if (age < 0 || age > 150) {
        // 手动抛出非法参数异常
        throw new IllegalArgumentException("年龄数值不合法！");
    }
}
```

### 3.4 throws 与 throw 的区别

| 对比维度 | throws             | throw                    |
| :------- | :----------------- | :----------------------- |
| 作用     | 声明可能出现的异常 | 主动抛出具体异常对象     |
| 位置     | 方法签名后         | 方法内部                 |
| 语法     | 可跟多个异常类型   | 每次只能抛出一个异常对象 |
| 性质     | 被动声明           | 主动触发                 |

## 四、多重捕获块

```java
try {
    需要检测的代码(可能会抛出异常，也可能不会抛出异常)
} catch (异常的类型1 异常类型的变量1) {
     捕获异常后处理异常
} catch (异常的类型2 异常类型的变量2) {
     捕获异常后处理异常
} catch (异常的类型3 异常类型的变量3) {
     捕获异常后处理异常
} finally {
     一定会被执行的代码(不管异常抛不抛出都会执行，例如数据库释放连接)
}
```

多个 catch 捕获不同异常，**子类异常必须在前，父类异常在后**，若父类异常在前，子类异常会被屏蔽，永远无法触发

```java
try {
    FileInputStream fileInputStream = new FileInputStream("a.txt");
    fileInputStream.read();
} catch (FileNotFoundException e) {
    e.printStackTrace();
} catch (IOException e) {
    e.printStackTrace();
} finally {
    System.out.println("finally");
}
```

> **JDK7+** 支持多异常合并捕获：`catch (异常1 | 异常2 e)`，异常类型必须**无继承关系**

## 五、自定义异常

Java 自带异常无法满足业务场景时（如：用户不存在、密码错误），可自定义业务异常。

```java
// 继承 Exception（受检异常，必须捕获/抛出）
public class CustomException extends Exception {
    public CustomException(String message) {
        super(message);
    }
}
```

使用方法：

```java
public void login(String username, String pwd) throws CustomException {//要注意抛出异常
    if (!"admin".equals(username)) {
        throw new CustomException("用户名不存在");
    }
}
```
